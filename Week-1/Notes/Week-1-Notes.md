# Week-1 Notes — Design Patterns, DSA, PL/SQL, TDD, Logging

## Design Patterns Quick Reference
| Pattern | Type | Intent |
|---|---|---|
| Singleton | Creational | One instance, global access |
| Factory Method | Creational | Delegate object creation to subclasses |
| Builder | Creational | Construct complex objects step by step |
| Observer | Behavioral | Notify dependents on state change |
| Strategy | Behavioral | Swap algorithms at runtime |
| Decorator | Structural | Add behavior dynamically |
| MVC | Architectural | Separate Model, View, Controller |
| Dependency Injection | Architectural | Inject dependencies, don't create them |

## DSA Quick Reference
| Structure | Best For | Insert | Search | Delete |
|---|---|---|---|---|
| Array | Index access | O(n) | O(n) / O(log n) sorted | O(n) |
| LinkedList | Queue/Stack | O(1) | O(n) | O(1) with ref |
| HashMap | Key-value lookup | O(1) avg | O(1) avg | O(1) avg |
| BST | Sorted data | O(log n) | O(log n) | O(log n) |
| Queue | FIFO processing | O(1) | O(n) | O(1) |

## Key Principles
- **SOLID**: Single Responsibility, Open/Closed, Liskov, Interface Segregation, Dependency Inversion
- **DRY**: Don't Repeat Yourself
- **KISS**: Keep It Simple, Stupid
- **YAGNI**: You Aren't Gonna Need It
